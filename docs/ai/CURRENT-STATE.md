## Partner Job Visibility Fix — 2026-08-12

The Partner Mobile screenshot showing Amit Verma online with no jobs was traced
to an eligibility mismatch: order-item dispatch used the explicit
`partner_services` link and category, while the Partner API list/detail/accept
queries also required the profile sub-category to exactly equal the service
sub-category. A valid request could therefore be created but hidden from the
partner and impossible to accept.

The redundant profile sub-category hard filter was removed from those Partner
API paths. Partners still need an explicit service link, matching category,
active status, and available status. Partners with no service link are not
expected to receive jobs.

The document overview status was also corrected so a partner with uploaded
documents all approved is marked approved when no document types are mandatory.
The Partner Mobile order-item type now includes the payment fields returned by
the API.

Server and Partner Web production builds, Partner Mobile type-check, and
`git diff --check` passed. After restart, Amit’s authenticated order-item job
endpoint returned two pending AC Service requests.

- Legacy bookings coexist with itemized orders; operational monitoring must read
  both models without destructively merging their schemas.
- Partner assignment is dispatch-driven rather than customer-selected.
