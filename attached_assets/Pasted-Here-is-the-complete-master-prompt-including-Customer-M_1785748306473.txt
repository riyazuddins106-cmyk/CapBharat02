# Replit AI Master Prompt – Implement Advanced Marketplace Booking, Scheduling & Service-Wise Payment System

## Objective

Upgrade the existing application into a professional **Urban Company-style marketplace platform**.

The current system already has:

* Customer Mobile App (React Native / Expo)
* Customer Web App (React)
* Partner Mobile App
* Admin Panel
* Backend APIs and Database

**Do not redesign the UI.**
**Do not replace existing architecture.**
**Do not break existing functionality.**

Analyze the existing codebase and enhance the current booking workflow.

The goal is to support:

* Multiple services in one order
* Multiple partners in one order
* Different service durations
* Parallel service execution
* Dynamic time slot booking
* Partner availability management
* Service-wise payments
* Partial partner acceptance
* Individual service cancellation
* Complete marketplace workflow

# 1. New Booking Architecture

Currently:

```
One Booking = One Service = One Partner
```

Change to:

```
Master Order

        |
        |
        ├── Service Booking 1
        |          |
        |          └── Partner Assignment
        |
        ├── Service Booking 2
        |          |
        |          └── Partner Assignment
        |
        └── Service Booking 3
                   |
                   └── Partner Assignment
```

One customer checkout can create multiple service bookings.

---

# 7. Customer Displayed Service Window

Customer should see:

```
Expected Service Window

10:00 AM - 1:00 PM

Approx Duration:
3 Hours
```

The customer duration should be based on the longest service.

Do not add durations together.

Wrong:

```
AC 1 hour
+
Cleaning 3 hours

Total 4 hours ❌
```

Correct:

```
Longest service = 3 hours ✅
```

# 8. Partner Calendar Management

Each partner calendar should block only their assigned service duration.

Example:

AC Technician:

```
10:00 AM - 11:00 AM
```

Cleaning Partner:

```
10:00 AM - 1:00 PM
```

AC technician becomes available after 11 AM.

Cleaning partner becomes available after 1 PM.

# 13. Search Optimization

Do not search forever.

Implement controlled searching:

First:

* Nearby partners
* Available partners
* Matching skills

Then:

* Expand search radius
* Retry periodically

Stop searching when:

* Partner accepts
* Customer cancels service
* Search timeout reached
* Service time expires

Admin should be able to configure timeout.
