After insert, it calls:

✅ The listJobs query is logically correct. It returns a booking if either:

bookings.professional_id = this_partner, OR
There exists a booking_partner_requests row where partner_id = this_partner AND status = 'pending'
The problem is NOT the listJobs query. The problem is that dispatch.broadcast() never creates those rows in the first place.

ROOT CAUSE
professionals.availabilityStatus defaults to 'offline' (schema line 21), and dispatch.broadcast() exclusively selects partners where availabilityStatus = 'available' (dispatch.service.ts line 44).

The test partner seeded by seed-test-accounts.ts starts with availability_status = 'offline'. Dispatch finds zero candidates, returns early without inserting any booking_partner_requests rows, and the partner's listJobs query has nothing to return.

SECONDARY CAUSES
B — partnerServices mismatch (dispatch.service.ts lines 38–39): The query starts from partnerServices INNER JOIN to professionals. If the test partner has no rows in partner_services matching first.service.id, they are excluded before the availability filter even runs. This is a second independent gate.

C — Document verification gate (dispatch.service.ts lines 50–76 + partner.service.ts lines 156–178): If document_type_configs contains any is_mandatory = true AND is_active = true rows, partners must have all of them in approved status. The updateAvailability endpoint enforces this too — you cannot even set availabilityStatus = 'available' without passing the doc check.

D — Only first service ID dispatched (booking.controller.ts line 91 first.service.id): Multi-item carts only dispatch based on the first service, meaning a partner must offer specifically that service.

Set the test partner's availability to 'available':

INSERT INTO partner_services (partner_id, service_id)

FROM professionals p, services s
WHERE p.name = 'Test Partner'   -- adjust to match seeded name
  AND s.is_active = true
ON CONFLICT DO NOTHING;

Fix 3 — Check/clear mandatory document gates
If document_type_configs has mandatory entries, either approve the partner's docs via the admin panel, or for development deactivate the mandatory flag:

UPDATE document_type_configs SET is_mandatory = false;

Fix 4 — Code: seed script should set availabilityStatus = 'available'
In server/src/database/seed-test-accounts.ts, the professional insert (or a follow-up update) should set availability_status = 'available' for the test partner so the dispatch flow works out of the box.

Fix 5 — Code: dispatch should use ALL booked service IDs, not just the first
In booking.controller.ts line 91, first.service.id should be replaced with all service IDs from the cart items, and dispatch.broadcast() should be updated to accept an array and use inArray(partnerServices.serviceId, serviceIds) — matching partners who offer ANY of the booked services.
